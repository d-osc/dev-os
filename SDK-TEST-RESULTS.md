# DPK SDK 0.1.0 test results

## Current schema: metadata launcher + window (Python SDK 0.4.0 / TypeScript SDK 0.5.0)

- Removed runtime/entry_point from launcher. Launcher supports name/comment/icon/categories only; window is the single execution configuration for both `dev launch` and `dev open`.
- Regression suite: Linux 87 passed; Windows 81 passed and 6 POSIX skips. Tests now reject launcher execution fields and verify both commands use the same unchanged window configuration.
- TypeScript rejects obsolete fields at type-check and runtime-validation levels. Real Linux/WSLg consent, sandboxed X11 rendering and uninstall tests passed.
- Older runtime/entry-point override reports below are historical and superseded. OS image/ISO not rebuilt.

## Launcher runtime update: Python SDK 0.3.2 / TypeScript SDK 0.4.2

- Core regression suite: Linux 87 passed; Windows 81 passed, 6 POSIX skips.
- `launcher.runtime` accepts native/node/bash/sh/python independently of window. Missing runtime inherits window, and native validation applies to the effective launcher entry point.
- Real Linux/WSLg test passed with a Python launcher and sh window declaration; consent opened the correct X11 window. Arguments remain inherited from window and `dev open` retains the original declaration.
- SDK runtime/type validation and packaged release checks passed. This update does not rebuild the OS image/ISO.

## Launcher entry-point update: Python SDK 0.3.1 / TypeScript SDK 0.4.1

- Core tests: Linux 86 passed; Windows 80 passed and 6 POSIX skips.
- Optional `launcher.entry_point` validates a packaged path and native executable membership in both SDKs.
- Runtime tests verify `dev launch` selects the override while `dev open` retains the original window entry, including preserved runtime/args and unchanged metadata.
- Real Linux/WSLg launcher test rendered a window from the override while the default window entry was deliberately set to a failing script. Permission denial and uninstall checks also passed.
- SDK artifacts rebuilt as `devos-dpk-sdk-0.4.1.tgz`, `devos_dpk_sdk-0.3.1-py3-none-any.whl`, and portable `dpk-sdk.pyz`. No OS image/ISO rebuild in this update.

## Current launcher release: Python SDK 0.3.0 / TypeScript SDK 0.4.0

- Python/core suite: Linux 84 passed; Windows 78 passed and 6 POSIX skips.
- TypeScript validates `LauncherConfig`, packaged icons, window requirement, forbidden custom exec/terminal fields, metadata injection and reserved installer inventory. Release tests cover 6 integration cases plus public type checking.
- Real Linux/WSLg test (`scripts/test-desktop-launcher.py`) passed: GIO parses the desktop entry (substituting the absent host `/usr/bin/dev` path for parsing only), noninteractive implicit grants fail, declining launches nothing, explicit consent renders an X11 window through the sandbox, background is not auto-started, uninstall removes the desktop entry.
- Runtime report and screenshot: `out/launcher-tests/result.json` and `out/launcher-tests/native-window.ppm`. No full desktop menu click test was performed; this host uses WSLg.
- Launcher uses `Terminal=true` for per-launch consent. No grants are stored automatically. The source OS remains CLI until a desktop environment and required runtimes are available.
- Artifacts: `out/sdk/devos-dpk-sdk-0.4.0.tgz`, `out/sdk/devos_dpk_sdk-0.3.0-py3-none-any.whl`, and `out/sdk/dpk-sdk.pyz`.
- These features are not yet included in the current OS image/ISO.

- CLI coverage: CLI-only format 2, all runtime declarations, generated command inventory, install/remove, reserved names, missing entry points, invalid arguments, payload/command conflicts, modified launchers, rollback and shell argument forwarding without evaluation.

## TypeScript SDK 0.2.0 — Node.js implementation

Supersedes the Python bridge in 0.1.0. The SDK now implements manifest validation, streaming TAR/gzip, hashing, verification, atomic packaging and scaffolding directly in TypeScript/Node.js. No Python bridge or zipapp is shipped in the npm package.

- Windows Node 24.18.0 and Linux Node 22.23.2: strict TypeScript compilation and all 4 integration tests passed, both in the checkout and after installing the release tarball in a separate temporary project.
- Pack/verify succeeds with an empty PATH: the SDK does not invoke external executables.
- Coverage includes malformed manifests, unknown/duplicate permissions, invalid runtime/args, symlinks (Linux), traversal, duplicate/missing archive members, checksum corruption, truncated gzip, PAX/Unicode names, overwrite protection and deterministic output.
- Compatibility tested in both directions on Windows/Linux: TypeScript archives install/remove with the existing Dev OS manager; archives built by the existing manager verify with the TypeScript SDK. Python is used only to run that existing manager in the compatibility test.
- Linux: Node/Bash/sh/native desktop starters compiled with `node build.mjs`, produced x86_64 ELF binaries and packed successfully without Python. This validates compilation/packaging, not a new desktop UI launch test.
- Release: `out/sdk/devos-dpk-sdk-0.2.0.tgz`. Checksums: `out/sdk/TYPESCRIPT-SHA256SUMS`.
- Default scaffold is now Node background; desktop scaffolds explicitly use `kind: 'window'` or `kind: 'both'` and require C/X11 compilation before packing. SDK packaging itself needs only Node.js and its npm dependencies.
